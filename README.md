# 才探 TalentRadar

[English](README.md) (default) · [简体中文](README.zh-CN.md)

An AI-powered recruiting workspace that aggregates public job postings from multiple
channels, parses resumes into structured candidate profiles, scores candidate–job fit
with an explainable five-dimension model, and drafts personalised outreach emails.

> This repository is a working prototype. The UI is Chinese; all contributions
> (issues, pull requests and commit messages) must be written in English — see
> [CONTRIBUTING.md](CONTRIBUTING.md).

## Features

| Module | What it does |
| --- | --- |
| Dashboard | Candidate / job / match / push statistics, source health and activity timeline |
| Candidates | Upload PDF / DOCX / TXT resumes, extract skills, experience, education and intent |
| Job Radar | Aggregated job library with filtering by **company site / WeChat official account / job board** |
| Data Sources | Configure, enable, pause and schedule collection tasks for the three channel types |
| Smart Matching | Explainable five-dimension score (skills / experience / education / city / salary) and a multi-company Top 100 ranking |
| Outreach | Generate recommendation letters in three tones and track delivery status |
| Settings | Company profile, SMTP, model and threshold settings |

The front-end runs in two modes:

- **Demo mode** (default when no backend is reachable): pure static site, state kept in
  `localStorage`, works even when opened directly via `file://`.
- **Online mode**: the page probes `GET /api/health`; when it answers, the full snapshot
  is loaded from the server and changes are synced back.

The UI intentionally shows only product-level status ("Online", "Demo data"). It does
not display the underlying Spring Boot / MySQL implementation details.

## Architecture

```
Browser (static HTML / CSS / JS, no build step)
   │  /api/*  (same origin in Docker, or http://localhost:8080 in dev)
   ▼
Spring Boot 3.2.5 (Java 21, Maven)
   ├── REST controllers: auth, candidates, jobs, matches, mails, sources, state, stats
   ├── JPA entities + repositories (MySQL 8 in production, H2 for local/tests)
   ├── StateService: bootstrap snapshot + seeded demo data
   ├── MarketJobService: public job pool from seed/market-jobs.json
   └── CrawlService + adapters: demo pool / user-configured web pages
   ▲
   │  seed/*.json (checked-in snapshots, generated by the Python crawlers)
   ▼
Python 3 crawlers (standard library only, no third-party packages)
   ├── crawl_market_jobs.py   → official career sites
   └── crawl_channel_jobs.py  → job boards + WeChat official accounts
```

- **Front-end**: plain ES5-style JavaScript, no framework and no bundler. Edit and refresh.
- **Back-end**: Spring Boot 3.2.5 / Java 21, Spring Data JPA, springdoc-openapi,
  PDFBox, Apache POI, jsoup.
- **Database**: MySQL 8 by default; an `h2` profile is provided for local verification.
- **Deployment**: `server/Dockerfile` serves the static front-end and the API from one
  origin on port 8080.

## Quick start

### Option 1 — Docker (recommended, front-end + API + MySQL)

```bash
cd server
docker compose up -d --build
docker compose ps
docker compose logs -f app
```

Open <http://localhost:8080/> (UI and API share the same origin).

- Swagger UI: <http://localhost:8080/swagger-ui.html>
- Health check: <http://localhost:8080/api/health>
- External MySQL access: `mysql -h127.0.0.1 -P13309 -utalent -ptalent123 talent_radar`

Stop with `docker compose down` (keeps the data volume) or `docker compose down -v`
(also removes the database volume).

### Option 2 — Run the backend locally

Requires JDK 21, Maven and a reachable MySQL 8 (defaults: `localhost:3306`,
`root` / `root`, database `talent_radar` is created automatically).

```bash
cd server
mvn spring-boot:run
# or, without MySQL, using the in-memory H2 profile:
mvn spring-boot:run -Dspring-boot.run.profiles=h2
```

Then open `index.html` through a local static server so that the page can reach the
backend (the backend allows CORS):

```bash
python3 -m http.server 4173
# http://localhost:4173/
```

`assets/js/config.js` falls back to `http://localhost:8080` when the same-origin probe
fails. Under `file://` the front-end stays in demo mode by design.

### Option 3 — Front-end only (no backend, no database)

Open `index.html` directly in a browser, or serve the repository root:

```bash
python3 -m http.server 4173
```

All data is seeded locally and persisted in `localStorage`.

### Build and test

```bash
cd server
mvn clean package
mvn test
```

## Job data and crawlers

The app keeps three checked-in data sets so it works offline:

| File | Consumed by | Purpose |
| --- | --- | --- |
| `assets/js/data.js` / `server/.../seed/state.json` | Job Radar page | The current job library (demo seed / server bootstrap) |
| `assets/js/real-jobs.js` / `server/.../seed/real-jobs.json` | "Collect now" | Verified public JD pool used by the demo collection adapter |
| `assets/js/market-jobs.js` / `server/.../seed/market-jobs.json` | Smart Matching | Whole-market pool for the Top 100 ranking |

Every job carries a real, individually verified detail URL. Jobs are grouped into three
channel types: **企业官网 (company career sites)**, **招聘平台 (job boards)** and
**微信公众号 (WeChat official accounts)**.

### Refreshing the job data

The crawlers use only the Python standard library (plus the system `curl` binary for a
site that blocks `urllib`):

```bash
# 1) Rebuild the official career-site pool (writes 454 company-site jobs)
python3 scripts/crawl_market_jobs.py

# 2) Append job-board and WeChat jobs, then sync every consumer seed file
python3 scripts/crawl_channel_jobs.py

# Inspect a sample without writing any file:
DRY_RUN=1 python3 scripts/crawl_channel_jobs.py
```

`crawl_channel_jobs.py`:

- collects **job boards** from Shixiseng, Zhaopin and Liepin. Zhaopin serves an
  anti-bot challenge page to `urllib`'s HTTP/1.1, so it is fetched with `curl`
  (HTTP/2) instead — an alternative fetch type for the same source;
- collects **WeChat official accounts** from a curated list of public recruitment
  articles, validates each article (HTTP 200, `og:title`, `js_content`, recruitment
  keywords), parses job lines and follows in-article links with a bounded BFS;
- keeps only jobs whose detail URL is real and reachable; guessed URLs are never
  generated;
- when a site is temporarily blocked, reuses the previously verified snapshot for
  that channel, so a single failed run never empties a channel in the UI;
- finally calls `sync_consumers()` to distribute representative jobs from both
  channels into **all** seed files (JSON and JS), including the job library and the
  "collect now" pool. Generated JS blocks are delimited by
  `/* CHANNEL_JOBS_START */ ... /* CHANNEL_JOBS_END */` markers and are safe to
  regenerate.

> Always run `crawl_market_jobs.py` **before** `crawl_channel_jobs.py`: the latter
> reads the company-site pool and appends the other two channels on top of it.

## Configuration

Front-end: `assets/js/config.js` (`apiBase`, `fallbackBase`, `autoDetect`, timeouts).

Backend (`server/src/main/resources/application.yml`, overridable via environment
variables):

| Variable | Default | Meaning |
| --- | --- | --- |
| `SERVER_PORT` | `8080` | HTTP port |
| `MYSQL_HOST` / `MYSQL_PORT` | `localhost` / `3306` | MySQL address |
| `MYSQL_DATABASE` / `MYSQL_USER` / `MYSQL_PASSWORD` | `talent_radar` / `root` / `root` | Database credentials |
| `JPA_DDL_AUTO` | `update` | Hibernate schema strategy |
| `SEED_ENABLED` | `true` | Seed demo data when the database is empty |
| `CRAWL_MODE` | `demo` | `demo` = verified JD pool, `web` = user-configured career pages |
| `MAIL_ENABLED` | `false` | `true` = real SMTP delivery, `false` = record only |
| `RESUME_PARSE_MODE` | `rule` | Rule-based resume extraction (`llm` is a placeholder) |
| `CORS_ORIGINS` | `*` | Allowed origins for the static front-end |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASSWORD` | — | Outbound mail settings |

Profiles: `docker` (compose), `h2` (in-memory DB), `test` (integration tests).

## API overview

| Endpoint | Description |
| --- | --- |
| `GET /api/health` | Health probe + storage type |
| `GET /api/bootstrap` | Full state snapshot (candidates, jobs, sources, mails, …) |
| `PUT /api/state` | Replace the full snapshot (prototype bridge) |
| `POST /api/auth/register`, `POST /api/auth/login` | Account management |
| `POST /api/candidates/upload` | Resume upload and parsing |
| `POST /api/jobs/collect` | Run a collection task |
| `POST /api/matches/market/import` | Import Top N market jobs into the job library |
| `POST /api/mails` | Create an outreach record |
| `POST /api/reset` | Restore seeded data |
| `GET /api/stats`, `GET /api/sources`, `GET /api/activities` | Statistics and lists |

Full reference: `/swagger-ui.html` when the backend is running.
